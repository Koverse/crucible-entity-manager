## Findings

1. **Critical — §5.4/§5.7: startup backfill can deadlock.** The source must enqueue backfill before releasing buffered live records, but the owner loop starts only *after* sources finish that work. A backfill larger than the bounded queue blocks `queue.put`, so startup never reaches the consumer. Evidence: [DESIGN.md:312](docs/DESIGN.md:312), [DESIGN.md:404](docs/DESIGN.md:404). **Recommendation:** start the owner loop before backfill and give each source an explicit catch-up state and cutover point.

2. **Critical — §5.4/D9: the startup watermarks can omit missing inputs.** The tracker uses the *newest measurement timestamp* across preloaded heads to query report *creation dates*; the fuser similarly uses a principal head to query component events. Those clocks and datasets differ, and one recently updated track can advance the watermark past missing events for every other track. The transformer’s newest output report has the same input/output cursor problem. Evidence: [DESIGN.md:321](docs/DESIGN.md:321), [tracker.py:1580](src/objectApps/correlators/entity_manager/entity_tracker.py:1580), [tracker.py:1582](src/objectApps/correlators/entity_manager/entity_tracker.py:1582). The 900-second cap also discards useful transformer and passthrough inputs; a filter reset cannot recover omitted events. **Recommendation:** use a durable cursor in each *source’s createdDate domain*, or query a conservative lookback and state explicitly that the cap loses data. Do not derive a global source cursor from the newest output head.

3. **Critical — §5.5: D4 does not make RollingUpdate overlap safe.** Each pod has its own filter, dedup set and head snapshot. Both can process the same input, append events, and race to overwrite an ENTITY head with different states. D4 only removes repeats *within one pod*. RollingUpdate also does not guarantee gap-free consumption: the optional health endpoint is off by default and startup preloads before subscribing. Evidence: [DESIGN.md:352](docs/DESIGN.md:352), [DESIGN.md:356](docs/DESIGN.md:356), [DESIGN.md:384](docs/DESIGN.md:384), [DESIGN.md:404](docs/DESIGN.md:404). **Recommendation:** remove the “overlap is safe” conclusion. Specify fencing or a single active writer and a subscription-ready handoff, or record concurrent state divergence and duplicate output as accepted rollout behavior. ENTITY upsert semantics make repeat head creates possible; they do not make competing state writes equivalent.

4. **Major — §5.5/D4: the proposed identities are neither universally present nor always duplicates.** The transformer copies an origin UUID to `source.uuid` only when present; the tracker sets `reportIds` only when that UUID is present. Worse, Kalman processing can skip an input row, but the writer later pairs output rows with input rows using `zip`, potentially assigning the *wrong* `reportIds`. An origin record rewritten under the same UUID can also carry a legitimate changed measurement, which `(trackId, source.uuid)` would suppress. Evidence: [transformer.py:189](src/objectApps/correlators/entity_manager/entity_transformer.py:189), [tracker.py:1104](src/objectApps/correlators/entity_manager/entity_tracker.py:1104), [tracker.py:1573](src/objectApps/correlators/entity_manager/entity_tracker.py:1573), [tracker.py:1502](src/objectApps/correlators/entity_manager/entity_tracker.py:1502), [DESIGN.md:345](docs/DESIGN.md:345). **Recommendation:** carry input identity alongside each output through filtering, define behavior for missing IDs, and distinguish a repeated version from a changed record. Test skipped rows, absent UUIDs, and same-UUID rewrites.

5. **Major — §5.4/D9: backfill is ordered against live traffic, but not within the backfill.** The tracker and fuser skip older measurements after a newer one has advanced the prior. Their built-in SSE SQL is compatible with adding a createdDate predicate, but neither query orders by measurement time; paging by createdDate alone can still deliver an older kinematics timestamp later. Evidence: [DESIGN.md:312](docs/DESIGN.md:312), [tracker.py:959](src/objectApps/correlators/entity_manager/entity_tracker.py:959), [fusion_filter.py:308](src/objectApps/correlators/entity_manager/entity_fusion_filter.py:308), [tracker.py:1551](src/objectApps/correlators/entity_manager/entity_tracker.py:1551), [fuser.py:1215](src/objectApps/correlators/entity_manager/entity_track_fuser.py:1215). **Recommendation:** specify stable pagination and per-key measurement-time ordering before applying historical rows, with a tie breaker and tests where createdDate and kinematics time disagree.

6. **Major — §5.4: slow or failed backfill has no completion rule.** A bounded live buffer eventually blocks its SSE reader while a slow query runs; with no replay, a subsequent disconnect creates another gap. The design does not say whether query failure retries, fails startup, releases buffered live data, or abandons the interval. Evidence: [DESIGN.md:312](docs/DESIGN.md:312), [DESIGN.md:327](docs/DESIGN.md:327), [DESIGN.md:747](docs/DESIGN.md:747). **Recommendation:** define a bounded catch-up deadline, retry and failure state, buffer-full behavior, and a cursor for a gap that grows during backfill.

7. **Major — §4/§5.3/D2: memory is still not bounded by the stated limits.** Known IDs and associations are never evicted, and pending writes are limited to one *per key* with no bound on the number of keys. The D4 set has the same problem for continuously active keys unless entries have their own expiry and rate cap. Evidence: [DESIGN.md:139](docs/DESIGN.md:139), [DESIGN.md:246](docs/DESIGN.md:246), [DESIGN.md:261](docs/DESIGN.md:261), [DESIGN.md:352](docs/DESIGN.md:352). **Recommendation:** set total cardinality or byte limits and an existence-check path when ID or association entries leave memory; bound pending writes globally.

8. **Major — §5.7: the drain deadline is not enforced by a 15-second HTTPX timeout.** `TimeoutConfig` supplies separate connect, read, write and pool timeouts, not one wall-clock deadline. A request begun late in the drain, or a retry and sub-chunk sequence, can outlive 20 seconds while its thread continues. Exiting 0 after dropping writes also hides the loss from Executor status. Evidence: [DESIGN.md:412](docs/DESIGN.md:412), [DESIGN.md:419](docs/DESIGN.md:419), [controller.py:31](site-packages/cruciblelib/controllers/v2/controller.py:31), [entity_utils.py:514](src/objectApps/correlators/entity_manager/entity_utils.py:514). **Recommendation:** stop launching writes when their remaining budget is insufficient, bound the whole write operation including retries, and report unfinished authoritative writes as an unsuccessful drain.

9. **Minor — §5.4: “complete supersede map” overstates the reload.** The stated reload retains the baseline 30-day lookback. A still-effective SUPERSEDE older than that is absent after restart or reconnect, regardless of gap length. Evidence: [DESIGN.md:285](docs/DESIGN.md:285), [DESIGN.md:330](docs/DESIGN.md:330), [entity_utils.py:1320](src/objectApps/correlators/entity_manager/entity_utils.py:1320). **Recommendation:** either load all effective management state or describe the 30-day limit as a recovery limitation.
