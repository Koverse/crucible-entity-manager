## Findings

1. **Critical — §5.5, D4: equal timestamps are not duplicate IDs.** The proposed `timestamp <= prior.timestamp` rule would discard a legitimate second measurement when two component tracks in a supersede group report at the same time. The current fuser sorts and processes both, and its filter rejects only *older* measurements ([fuser.py:885](src/objectApps/correlators/entity_manager/entity_track_fuser.py:885), [fusion_filter.py:308](src/objectApps/correlators/entity_manager/entity_fusion_filter.py:308)). Also, a skipped filter update does not by itself suppress the principal event: the current fuser still appends it ([fuser.py:923](src/objectApps/correlators/entity_manager/entity_track_fuser.py:923)). **Recommendation:** deduplicate by a stable input identity, scoped to the component track, and specify whether a duplicate produces an output row.

2. **Critical — §5.2: independent fuser pods cannot safely route by a changing supersede root.** Each pod would consume the component and management streams independently. If one has applied `A → B` and another has not, both can accept the same component event under different owners; the result is not bounded to “at most one extra principal event.” The baseline has one dispatcher applying one map before routing its event batch ([fuser.py:631](src/objectApps/correlators/entity_manager/entity_track_fuser.py:631), [fuser.py:664](src/objectApps/correlators/entity_manager/entity_track_fuser.py:664)). Nor is the new owner guaranteed to hold the root’s prior: preload is limited and principal heads without a component association use a fallback shard hash ([fuser.py:570](src/objectApps/correlators/entity_manager/entity_track_fuser.py:570), [fuser.py:591](src/objectApps/correlators/entity_manager/entity_track_fuser.py:591)). **Recommendation:** require one fuser partition until routing uses a shared ordered stream and an explicit ownership handoff.

3. **Critical — §§5.4, 5.5: heads do not provide the claimed full recovery.** Existing-head updates are deliberately best effort and may be dropped ([tracker.py:1465](src/objectApps/correlators/entity_manager/entity_tracker.py:1465), [fuser.py:1014](src/objectApps/correlators/entity_manager/entity_track_fuser.py:1014)). A restarted pod can therefore preload an older prior. The design also has no cursor or barrier covering events between its preload query and SSE subscription; §10 leaves SSE replay unresolved. **Recommendation:** establish replay and a preload-to-stream handoff, or narrow the recovery guarantee and document the resulting loss window.

4. **Major — §5.5: the head-create race is not the only rollout hazard.** Overlapping pods each have local state and can append duplicate events. The duplicate detector’s suppression set is process-local ([duplicate_identifier.py:46](src/objectApps/correlators/entity_manager/entity_duplicate_identifier.py:46), [duplicate_identifier.py:1100](src/objectApps/correlators/entity_manager/entity_duplicate_identifier.py:1100)); two runs may also choose from different head snapshots before appending SUPERSEDE events ([duplicate_identifier.py:1042](src/objectApps/correlators/entity_manager/entity_duplicate_identifier.py:1042), [duplicate_identifier.py:1158](src/objectApps/correlators/entity_manager/entity_duplicate_identifier.py:1158)). “Latest event wins” also makes a competing RESTORE relevant. **Recommendation:** require non-overlapping ownership or fencing before calling these writes overlap-safe; test concurrent duplicate-detector runs and RESTORE races.

5. **Major — §§2, 5.3, 8: failed head creates do not retain the withheld events.** The baseline keeps the head ID for retry but filters its events out of that cycle’s output; there is no pending-event buffer carrying those records into the next cycle ([tracker.py:1435](src/objectApps/correlators/entity_manager/entity_tracker.py:1435), [tracker.py:1499](src/objectApps/correlators/entity_manager/entity_tracker.py:1499)). The design’s “held back and retried” wording promises more than this code does. **Recommendation:** specify a bounded pending-event buffer and retry policy, or explicitly state that those events are dropped.

6. **Major — §§4, 5.3, D2: the stated memory bounds are incomplete.** The owner’s `max_batch_records` limit applies after a source batch has entered the queue; the SSE listener parses and enqueues a whole payload ([entity_utils.py:249](src/objectApps/correlators/entity_manager/entity_utils.py:249)). Evicting a prior also leaves lifetime-growing known-ID and association maps, while evicting those maps can make an existing head look new ([tracker.py:369](src/objectApps/correlators/entity_manager/entity_tracker.py:369), [fusion_filter.py:77](src/objectApps/correlators/entity_manager/entity_fusion_filter.py:77), [fusion_filter.py:164](src/objectApps/correlators/entity_manager/entity_fusion_filter.py:164)). **Recommendation:** bound payload size before enqueueing, and define separate eviction and existence-check rules for priors, known IDs, associations, and pending writes.

7. **Major — §5.3: bounded writer concurrency does not preserve per-key event order.** The tracker currently sends successive waves with at most one event per track per wave ([tracker.py:1510](src/objectApps/correlators/entity_manager/entity_tracker.py:1510)). The proposed `WritePlan`/`BatchWriter` description retains head-before-event ordering but says nothing about serializing successive events for one key. The 5731 writer’s fixed workers can execute chunks concurrently ([writer.py:33](k5731/objectApps/correlators/correlator_core/writer.py:33)). **Recommendation:** retain per-key write serialization and test a slow first chunk followed by a faster later event.

8. **Major — §§5.7, 5.10: the 20-second drain has no enforceable I/O deadline.** Synchronous controller calls placed in `asyncio.to_thread` cannot be stopped merely by cancelling their awaiting task; the current controller timeout configuration allows a 120-second read ([entity_utils.py:313](src/objectApps/correlators/entity_manager/entity_utils.py:313)). **Recommendation:** give each request a deadline compatible with the drain budget, define what happens to unfinished writes, and test shutdown during a stuck request.

9. **Major — §§5.8, 7, 8: supported operational modes silently disappear.** The proposed CLI has no replacement for the fuser’s default CI mode, `--no-ci`, fixed `--ci-omega`, or `--passthrough` ([fuser.py:1261](src/objectApps/correlators/entity_manager/entity_track_fuser.py:1261), [fuser.py:1303](src/objectApps/correlators/entity_manager/entity_track_fuser.py:1303)). It likewise omits the duplicate detector’s poll and detection thresholds ([duplicate_identifier.py:1344](src/objectApps/correlators/entity_manager/entity_duplicate_identifier.py:1344)). **Recommendation:** carry these settings into validated configuration with current defaults, or record each removal as a deliberate behavior change.

10. **Major — §9.1: `test_principal_track_kalman.py` is not object-only.** The table discards it wholesale, but it contains entity construction, supersede-chain and restore tests, plus entity velocity-column and CI cases ([test_principal_track_kalman.py:121](src/objectApps/correlators/tests/unit/test_principal_track_kalman.py:121), [test_principal_track_kalman.py:187](src/objectApps/correlators/tests/unit/test_principal_track_kalman.py:187), [test_principal_track_kalman.py:470](src/objectApps/correlators/tests/unit/test_principal_track_kalman.py:470)). **Recommendation:** review those behaviors for porting even if the old module and test file are discarded.

11. **Minor — §§3, 5.10, 10: narrow two platform claims and close one answered question.** Resource fields are absent from the **Spring execution template**, but exist in the Go CRD and are passed to containers by the operator ([ExecutionTemplate.java:17](executor/crucible/crucible-services/src/main/java/com/crucible/services/service/execution/model/ExecutionTemplate.java:17), [execution_types.go:56](executor/crucible-executor/api/v1alpha1/execution_types.go:56)). Installed cruciblelib also has native async operations; its synchronous requests refresh through `token_provider` when the token is near expiry, so Q3 is substantially answered by source ([controller.py:233](site-packages/cruciblelib/controllers/v2/controller.py:233), [controller.py:272](site-packages/cruciblelib/controllers/v2/controller.py:272), [controller.py:574](site-packages/cruciblelib/controllers/v2/controller.py:574)). **Recommendation:** identify the Spring model as the resource gap, describe only the chosen controller methods as synchronous, and replace Q3 with a focused integration test.
